Start with approved Word content

Select a .docx source and an Adobe LiveCycle / AEM Forms Designer .xdp template, then compare. This application runs from a local HTML file. It contains all its code and makes no network requests.

Review before updating

Each XDP text block is matched to Word paragraphs. Exact text is separated from suggested and ambiguous matches. Pick an alternative, search the Word source, or edit a replacement. Click Approve update only after checking the mapping and wording. No updates are pre-approved.

Keep review decisions portable

Save a JSON review to retain proposed wording, source mappings and notes. Load it after comparing the same files. Text guards reject stale mappings, and restored approvals always need approval again. The CSV is a human-readable change list, not an import format.

Preserve the template

Only existing text-node spans in supported static draw values and field captions are patched. Scripts, bindings, geometry, XML namespaces, comments and other packets are not rewritten. UTF-8 / UTF-16 encoding and BOM are preserved. Rich-text wrappers remain in place; changed words inherit nearby run formatting.

Know the limits

Unmatched wording is not proof that an object should be added or deleted. Field values, choice-list options, tooltip/validation text, images, generated text, inherited prototypes and structural/layout changes are outside the automatic update scope. Scripted or bound objects are blocked for export. Signed/encrypted XDPs are comparison-only. Word revisions use a final-text approximation, not the Word layout engine. List numbering, images and unsaved field results are not reconstructed.

Rich-text line breaks must retain their existing structure. New paragraphs or empty replacements need Designer review. Word formatting is not imported. A browser cannot validate the Adobe runtime behavior of a form.

More reliable recurring reviews

Optional: wrap a Word paragraph in a content control and set its Tag to xdp:YOUR_UNIQUE_XDP_OBJECT_ID. Use the object's actual id attribute, not its display name. For multi-paragraph rich text, use xdp: followed by the exact block path shown in the review. IDs must be unique. Tagged matches still require approval.

Browser & privacy

Use a current desktop Chrome or Edge browser. The app checks for native raw-DEFLATE support. Files and proposals stay in memory; reloading clears them. Exported review reports contain your document text, so protect them like the original files. Browser extensions and your device's security policies remain outside this app's control.
