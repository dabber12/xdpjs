What this tool does—and what it does not

The standalone HTML runs directly from your local disk. Its code, ZIP reader, and test document are included; there are no CDN requests, remote fonts, analytics, uploads, or server calls. The page’s content security policy blocks network connections. Use trusted input files and a browser without intrusive extensions for sensitive work.

Editable conversion

Choose a DOCX, inspect the preview and coverage audit, then create a draft XDP. In this mode ordinary paragraphs, styled runs, common list formats, raster pictures, simple sections, headers/footers, and tables are mapped to browser layout and measured. Native text objects are split across rendered lines and spatial gaps, and are never merged across source blocks. A word option gives smaller objects. Different layout engines, missing fonts, unsupported Word properties, and font baselines can still change the result.

Appearance-fragment conversion

For artwork that follows an authoritative Word rendering, export every page to lossless PNG at a known DPI using your local Word/PDF workflow. Load those pages under Fidelity checks, select “Image fragments · Word reference PNGs”, and set the matching DPI. The tool crops small non-overlapping PNG fragments and stores them as XFA image draws at fixed physical coordinates. Source raster reconstruction is checked pixel for pixel. Visible text is artwork, not editable XFA text. Browser-preview image mode locks only the browser’s approximation, not Word’s output.

Actual Adobe verification

Open the generated draft in your installed LiveCycle or AEM Forms Designer, render/export it locally, and rasterize its pages at the same DPI as the Word reference pages. Load the resulting PNGs and compare. With tolerance zero, any changed RGB pixel fails exact raster equality. Mismatched page counts, dimensions, or physical page geometry fail rather than being adjusted. Positive tolerances are diagnostics, never a claim of identity. Adobe rendering is not available inside this HTML tool.

Safety and limits

Files stay in browser memory until you download an output. Clear session reloads the app; no localStorage, cookies, service worker, or database is used. External relationships are not followed. Embedded HTML and active SVG are not executed. ZIP counts and declared expansion sizes are checked, but this is not a hardened malicious-file sandbox. Inputs are limited to 40 MiB, expanded packages to 160 MiB, individual parts to 32 MiB, pages to 200, rasters to 40 million pixels, and draws to 180,000. Memory use can still be substantial. Use smaller batches for image-heavy documents.

Known fidelity limits

This implementation does not reproduce the complete Word layout model. Examples include floating drawings/text boxes, equations, charts, SmartArt, footnotes/endnotes, automatic hyphenation, complex scripts, document-grid snapping, all conditional table styles, continuous-section layout, column balancing, decorative borders, and embedded-font handling. Many known cases are detected and block native export by default. Detection is conservative, not exhaustive. Editable text is static positioned boilerplate, not responsive form fields; editing longer text can overlap nearby fragments.
