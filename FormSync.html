XDP / XFA template source
XFA 3.3 template. Default mode uses flowed section subforms and growable paragraph-rich-text draws. Page masters define page geometry; they are not frozen browser pages. Legacy modes use fixed positions. No scripts, external resource URLs, or data bindings are emitted.


What this tool does—and what it does not
The standalone HTML runs directly from your local disk. Its code, ZIP reader, and test document are included; there are no CDN requests, remote fonts, analytics, uploads, or server calls. The page’s content security policy blocks network connections. Use trusted input files and a browser without intrusive extensions for sensitive work.
Default: flowed paragraphs and tables
One source paragraph or list item becomes one growable rich-text draw, including all bold/italic/color spans. Ordinary spaces, OOXML run boundaries, browser line wraps and browser page boundaries do not create XDP objects. Adjacent identical text styles are coalesced. Manual line breaks remain inside the paragraph; explicit page breaks may split a paragraph into logical parts. Separate paragraphs, table cells and other source blocks remain separate. Body subforms use layout="tb"; tables use layout="table" and rows use layout="row". Text has no x/y coordinates and no fixed height. The target renderer chooses wrapping and page count. Page margins and header/footer anchors still use page coordinates, as page masters must.
The exporter reads unpaginated source blocks rather than reverse-engineering the browser preview. Selecting word fragmentation or saved page-break hints in a legacy mode cannot affect flowed export. The browser preview is not an Adobe rendering. The object list shows source sections, not an asserted XDP page count.
Maintainability
The Structure tab is a hierarchy of named objects, not a flat word list. Names are derived from bookmarks, heading text, content-control labels, table labels and nearby content, with an identity suffix for uniqueness. Heading levels come from source outline properties and declared Heading styles, not guessed font sizes. Group wrappers add no padding, spacing, fixed height or keep-together rule. Paragraph keep-with-next behavior is propagated through wrapper boundaries. Source part, XML path, style and stable key are recorded in object metadata.
Choose a row to rename an object, then save a naming profile. Profiles preserve names where persistent source IDs still match. XML-path fallback names are deterministic for the same input. On a changed input, a saved fallback name is applied only when its source fingerprint still matches; otherwise it is left unmatched rather than assigned to a different paragraph. Structural changes can still invalidate group identities. No fuzzy matching guesses are made. A structure/style manifest and naming profile are also included in Output ZIP. Changes made later in Designer are not merged back into regenerated files. List labels are static text: inserting or reordering items in Designer requires updating their numbering.
Shared-style mode emits internal font/paragraph prototypes. Matching properties within the same source style are shared, with inline overrides for actual text differences. Disable this option to emit self-contained properties instead; the resolved values are tested for structural equivalence. Editing shared definitions affects their references on template reload. Designer may materialize or alter these references when saving: test your target version.
New in v7: source-driven conversion and verification
Default export uses plain source-model nodes and never reads browser-computed styles or mounts an export preview. Source addresses and fingerprints are namespace-aware; alternate content is selected by capabilities. Compatibility effects, source language, font faces and source-property layers are auditable. Default XDP bytes are reproducible: no generation timestamp is inserted.
The Validation & regeneration view offers independent emitted-subset checking, guarded declarative overrides, semantic comparisons, source-model export and local face/glyph inspection. Full XFA schema validation, Adobe rendering and Designer round trips are separate unrun stages, not implied by structural success. Experimental hard-feature probes are development-only and do not silently enable unsupported layouts.
New in v6: facing-page masters and source-text precision
Single-section documents with mirrored margins or different odd/even headers now use named native duplex page masters. A distinct first-page story remains separate; absent first/even stories stay blank. The Adobe renderer selects masters as content flows: the exporter does not pin each paragraph to a page or copy headers for every preview page. Multiple-section facing layouts remain blocked because Word section-local header parity and XFA physical parity are not interchangeable.
Binding gutters now change the correct source body dimension. A top gutter moves the body down and reduces its height without narrowing it; mirrored margins take precedence and put the gutter on the inside. The manifest records each master’s frame, story type and parity. Web-view-only hidden text remains visible in paginated output; actual hidden text still follows the existing hidden-text handling. Native character spacing and kerning are retained from resolved source properties, not rounded browser values. Styled manual line breaks and list-marker paragraph-mark formatting remain inside their paragraph draw.
These are source/XML mapping improvements, not a Word-identical rendering certificate. Adobe page selection, font metrics and rich-text leading still require a target-renderer comparison. Booklet and two-on-one imposition are now explicit blockers rather than silently approximated.
Native tables, live counters, and pictures
Repeating table headers remain experimental in permissive mode only. The draft stores leading header rows once in a named flowed overflow-leader group, but the XFA 3.3 text requires positioned leader subforms and descendants. Strict mode now blocks this unvalidated combination rather than asserting compatibility or introducing positioned header fragments. Fixed table/grid/cell width preferences are reconciled in point units with the original constraints retained. An omitted source table-layout property now correctly means AutoFit; content-dependent AutoFit remains blocked in strict mode. Fixed-layout noWrap no longer incorrectly disables line breaking. Leading/trailing grid gaps keep their real column slots without creating text objects.
Single-paragraph center/bottom-aligned cells can use a direct row draw and native paragraph vertical alignment, retaining cell padding, fill and column spans. Multiple-paragraph or specially bordered/live-counter cells remain blocked for non-top alignment rather than being merged. General vertical merges are still blocked; malformed merges and significant continuation content are detected to prevent silent loss.
PAGE, NUMPAGES and SECTIONPAGES values remain inside their paragraph via native embedded-text references. Only actual live counters add a hidden named helper field and application-generated layout-ready script. Source code is never evaluated. Fields retain font/color/superscript formatting; supported page formats include decimal, two-digit decimal, Roman and alphabetic. Source-locked fields retain their cached value. Adobe scripting and actual pagination must be tested; cached browser page numbers are not the final output. Unknown switches, unformatted totals in non-decimal sections, and PAGE in a potentially split body paragraph remain blockers. Roman formatting is implemented for positive values below 4000; counter values outside that range fall back to decimal and need checking.
Standalone pictures retain source-density pixels for flips, half turns and square-display quarter turns. Cropping is applied before the transform. Unchanged PNG/JPEG bytes remain untouched. Center/right picture alignment uses native draw alignment. These changes do not rasterize text.
Source-fidelity improvements in v4
Theme luminance transforms and color-scheme mappings, attribute-wise spacing inheritance, source character-width scale, native minimum line height and common tab leaders are retained. Table formatting now resolves first/last rows and columns, corner cells, horizontal/vertical bands, band sizes, default table styles and partial margin/border inheritance in semantic precedence order. These changes do not add word objects or body coordinates. Cell source metadata records the selected style regions. Browser previews do not reproduce native minimum leading, character scaling or leader metrics exactly; inspect the Adobe output.
Flow-specific coverage limits
Strict export blocks known unsupported flow features rather than switching to positions: run highlighting/shading; mixed text and inline pictures; general vertical table merges; repeating table headers (unvalidated leader layout), including nested/all-header cases; content-dependent AutoFit; multi-paragraph or otherwise unsupported non-top cell alignment; multi-section mirrored/even-page layouts; multiple columns; heavy/custom tab leaders; and unsupported or potentially split page fields. A permissive draft may differ or lose unsupported content. Review every warning. Repeating-header pagination, live-counter refresh, row vertical alignment and all other mappings still need actual Adobe/Word comparison.
Legacy positioned text
This optional snapshot mode is separate from the default. It still exports explicit positions and line/run fragments. Justification no longer silently forces word splitting: individual-word output requires the explicit word setting. A justified line snapshot is flagged because native justification belongs in the default flowed paragraph mode.
Appearance-fragment conversion
For artwork that follows an authoritative Word rendering, export every page to lossless PNG at a known DPI using your local Word/PDF workflow. Load those pages under Fidelity checks, select “Image fragments · Word reference PNGs”, and set the matching DPI. The tool crops small non-overlapping PNG fragments and stores them as XFA image draws at fixed physical coordinates. Source raster reconstruction is checked pixel for pixel. Visible text is artwork, not editable XFA text. Browser-preview image mode locks only the browser’s approximation, not Word’s output.
Actual Adobe verification
Open the generated draft in your installed LiveCycle or AEM Forms Designer, render/export it locally, and rasterize its pages at the same DPI as the Word reference pages. Load the resulting PNGs and compare. With tolerance zero, any changed RGB pixel fails exact raster equality. Mismatched page counts, dimensions, or physical page geometry fail rather than being adjusted. Positive tolerances are diagnostics, never a claim of identity. Adobe rendering is not available inside this HTML tool.
Safety and limits
Files stay in browser memory until you download an output. Clear session reloads the app; no localStorage, cookies, service worker, or database is used. External relationships are not followed. Embedded HTML and active SVG are not executed. ZIP counts and declared expansion sizes are checked, but this is not a hardened malicious-file sandbox. Inputs are limited to 40 MiB, expanded packages to 160 MiB, individual parts to 32 MiB, pages to 200, rasters to 40 million pixels, and draws to 180,000. Memory use can still be substantial. Use smaller batches for image-heavy documents.
V8 source-fidelity improvements
Numbering defaults, overrides, style links and restart triggers are source-resolved. Hanging indents and equivalent-unit tabs preserve inheritance. Tables retain supported row-level formatting exceptions and content-controlled rows/cells. Shared borders use documented Word conflict rules, with original and resolved edges in the manifest. Uniform whole-paragraph double strike uses native font properties. Script-specific font information and metric-only font requirements are audited. These mappings keep paragraph objects and flowing body layout. Source and emitted-grammar checks are not Word/Adobe visual verification.
Known fidelity limits
This implementation does not reproduce the complete Word layout model. Examples include floating drawings/text boxes, equations, charts, SmartArt, footnotes/endnotes, automatic hyphenation, complex scripts, document-grid snapping, conditional table geometry beyond cell formatting, continuous-section layout, column balancing, decorative borders, and embedded-font handling. Many known cases are detected and block native export by default. Detection is conservative, not exhaustive. Flowed text is static boilerplate editable in Designer, not fillable user-entry fields. It grows and flows by template rules, subject to target-renderer validation. Legacy positioned text does not reflow.
